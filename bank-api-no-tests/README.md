# Bank API

Небольшой, но "production-shaped" REST-сервис для банковских счетов и переводов:
Spring Boot 3 + Java 21 + PostgreSQL + Flyway. Сделан так, как реальный сервис
выглядел бы в проде — с явными инвариантами, идемпотентностью и тестами,
проверяющими корректность под конкуренцией, а не только happy path.

## Архитектура

```
controller/  → тонкий HTTP-слой: валидация запроса, маппинг в DTO, коды ответов
service/     → вся бизнес-логика и транзакционные границы (@Transactional)
domain/      → JPA-сущности с инвариантами внутри (Account.credit/debit не дают уйти в минус)
repository/  → Spring Data JPA + явные блокировки для денежных операций
dto/         → неизменяемые records для запросов/ответов, отделены от сущностей
mapper/      → entity → DTO конвертация
exception/   → доменные исключения + @RestControllerAdvice для единого формата ошибок
config/      → OpenAPI, correlation-id фильтр для трассировки логов
```

### Почему так, а не иначе

- **Деньги — `BigDecimal`, не `double`.** Плавающая точка на деньгах — это баг, а не стиль.
- **`Account.credit()/debit()`** — единственный способ изменить баланс. Инварианты
  (нельзя уйти в минус, нельзя изменить на отрицательную/нулевую сумму) живут
  в домене, а не размазаны по сервисам.
- **Идемпотентность переводов/депозитов/снятий.** Каждый запрос несёт
  `idempotencyKey` с уникальным ограничением в БД. Повторный вызов после таймаута
  сети не задвоит операцию — просто вернётся результат первого выполнения.
- **Блокировки при переводах.** `SELECT ... FOR UPDATE` на оба счёта, всегда
  в порядке возрастания UUID (`TransferService.lockAccountsInOrder`). Без
  фиксированного порядка два встречных перевода (A→B и B→A) в конкурентных
  транзакциях могут заблокировать друг друга навечно (deadlock). С фиксированным
  порядком — не могут.
- **`@Version` на `Account`** — optimistic locking как второй рубеж защиты от
  потерянных обновлений вне явно заблокированных путей.
- **`open-in-view: false`** — классический анти-паттерн ленивой загрузки во
  view-слое отключён осознанно.
- **Flyway, а не `ddl-auto: update`.** Схема версионируется и ревьюится как код.
- **Тест на конкурентность** (`TransferControllerIntegrationTest.concurrentTransfers...`)
  запускает 50 параллельных переводов по $1 и проверяет, что итоговая сумма на
  счетах сходится копейка в копейку — это и есть доказательство, что блокировки
  реально работают, а не просто выглядят правильно в коде.

## Запуск

### Локально с Docker Compose (проще всего)

```bash
docker compose up --build
```

API поднимется на `http://localhost:8080`, Swagger UI — на
`http://localhost:8080/swagger-ui.html`.

### Локально с локальным Maven + отдельным Postgres

```bash
docker run -d --name bank-postgres -e POSTGRES_DB=bankdb \
  -e POSTGRES_USER=bank -e POSTGRES_PASSWORD=bank -p 5432:5432 postgres:16-alpine

mvn spring-boot:run
```

### Тесты

```bash
mvn test
```

Интеграционные тесты сами поднимают эфемерный PostgreSQL через Testcontainers
(нужен установленный Docker), поэтому дополнительной настройки не требуется.

## API

| Метод | Путь                                  | Описание                              |
|-------|----------------------------------------|----------------------------------------|
| POST  | `/api/v1/accounts`                     | Открыть счёт                           |
| GET   | `/api/v1/accounts/{id}`                | Получить счёт и баланс                 |
| POST  | `/api/v1/accounts/{id}/deposits`       | Пополнить счёт (идемпотентно)          |
| POST  | `/api/v1/accounts/{id}/withdrawals`    | Снять со счёта (идемпотентно)          |
| POST  | `/api/v1/transfers`                    | Перевод между счетами (идемпотентно)   |

Пример запроса на открытие счёта:

```bash
curl -X POST http://localhost:8080/api/v1/accounts \
  -H "Content-Type: application/json" \
  -d '{"ownerName": "Alice", "currency": "USD", "openingBalance": "100.00"}'
```

Пример перевода (обязательно с `idempotencyKey`, генерируемым на стороне клиента):

```bash
curl -X POST http://localhost:8080/api/v1/transfers \
  -H "Content-Type: application/json" \
  -d '{
    "fromAccountId": "<uuid>",
    "toAccountId": "<uuid>",
    "amount": "30.00",
    "idempotencyKey": "c3f2a1e4-..."
  }'
```

## Что дальше стоило бы добавить в реальном проекте

Это учебный/демонстрационный срез, честно ограниченный по объёму. Для полноценного
прод-сервиса добавил бы: аутентификацию/авторизацию (Spring Security + OAuth2),
outbox-паттерн для публикации событий о переводах в Kafka, rate limiting на
уровне API gateway, аудит-лог отдельно от бизнес-таблиц, метрики Prometheus и
дашборды, contract-тесты (Pact) если это часть микросервисной экосистемы.
